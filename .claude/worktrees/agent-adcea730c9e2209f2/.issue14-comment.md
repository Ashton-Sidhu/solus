## Resolution

**Recommended endpoint set**
- **Bulk (all open PRs):** one GraphQL query — `pullRequests(first:30)` → last commit → `statusCheckRollup { state, contexts(first:100) }` + `mergeStateStatus`. `statusCheckRollup` merges check runs *and* commit statuses in one surface, and costs ~1 point for 30 PRs (formula: connection requests / 100, min 1) against a 5,000-pt/hr GraphQL budget that is separate from REST.
- **Focused PR:** REST `GET /repos/{o}/{r}/commits/{headSha}/check-runs` (`filter=latest`) + `GET .../commits/{headSha}/status`, both with stored ETags — authorized `304`s are rate-limit-free.
- **Required checks:** GraphQL `isRequired(pullRequestNumber:)` on `CheckRun`/`StatusContext` — readable by anyone who can view the PR and covers both legacy branch protection and rulesets (it's what `gh pr checks` uses). REST alternatives are worse under our classic `repo`-scoped token: `GET /branches/{b}/protection` is admin-only (403 for non-admins → the `unknown` state), and `GET /rules/branches/{b}` is readable with plain read access but sees rulesets only, not legacy protection. Treat protection 403/404 as "requiredness unknown", never "no required checks"; fall back to `mergeStateStatus` (`BLOCKED`/`UNSTABLE`) as the coarse gate signal (REST `mergeable_state`, already fetched by the provider).

**`PrChecksSummary` (Wave 0 contract sketch)**

```ts
type PrChecksState = 'pending' | 'passing' | 'failing' | 'unknown'
interface PrCheckItem {
  name: string
  kind: 'check_run' | 'status'
  status: 'queued' | 'in_progress' | 'completed' | 'expected'
  conclusion: 'success' | 'failure' | 'neutral' | 'cancelled' | 'skipped' | 'timed_out' | 'action_required' | 'stale' | null
  detailsUrl: string | null
  completedAt: string | null
}
interface PrChecksSummary {
  headSha: string                       // discard when the PR head moves
  state: PrChecksState                  // rollup over required when known, else all
  required: PrCheckItem[]
  optional: PrCheckItem[]
  requiredness: 'known' | 'unknown'     // 'unknown' ⇒ WS2 gates on mergeStateStatus instead
  mergeStateStatus: string | null       // CLEAN | BLOCKED | UNSTABLE | ...
  fetchedAt: string
}
```

**Cadence (activity-gated — recommended)**
- No idle polling; refresh on demand when the PR surface mounts/focuses.
- While Review Mode or the merge queue is active: GraphQL bulk every **60 s** (~1–2 pts/poll ≈ 2% of budget) + focused-PR REST with `If-None-Match` every **15–30 s** (free while unchanged). Resolve requiredness once per (PR, headSha), cache with ~10 min TTL.
- Poll-everything-always was rejected: 30 PRs × 2 REST calls at 60 s = 3,600 req/hr = 72% of the shared 5,000 req/hr REST budget.
- Implementation caveat for WS1: docs promise ETags on "most endpoints"; verify `/check-runs` returns stable ETags in practice (sandbox blocked empirical `gh api` verification here).
