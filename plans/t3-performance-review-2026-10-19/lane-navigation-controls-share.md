# Lane report: navigation-controls-share (2026-10-19)

Scope: T3 #20813 (Android navigation: Settings destination, expandable rail, retained list content), #20327 (native iOS segmented control), #21250 (PR Share). Implemented in the shared dirty checkout. No commit, build, dev server, install, or package/lock/config change.

## What changed

### #20813 Android navigation
- `apps/mobile/src/features/workspace/workspace-destinations.ts` (new): the destination rules. Settings is selected from the root stack while its pages (`SETTINGS_PAGE_ROUTES`) are on top; it is not stored in the tab reducer. Choosing Settings pushes it over the current location. Choosing the shown list tab from Settings pops only the settings pages. Choosing the other list tab pops to Home and selects it (the existing iPad sidebar-picker rule). History is never reset, so this does not copy T3's history drop.
- `use-workspace-destinations.ts` (new): the hook that applies a change (pop, select, navigate).
- `AndroidWorkspaceNavigation.android.tsx`: the phone bar now has Chats, Pull Requests, and Settings. New `AndroidWorkspaceRail`: 72dp collapsed, with a menu button, New session (shown only with paired hosts), and three icon destinations that carry accessibility names and selected state. It widens to 240dp over the panes with labels and a scrim. Back, the scrim, or a choice closes it. It narrows to 0 with the sidebar. Width and label motion use Reanimated with `ReduceMotion.System`. The `.tsx` stub was updated.
- `WorkspaceSettingsFrame.android.tsx` / `.tsx` (new): the screen layout for all settings pages, through a `Stack.Group screenLayout` in RootNavigator. On an Android phone the bar shows under Settings only when Settings lies directly on Home. Settings over a conversation stays an ordinary Back page. The tree stays the same whether the bar shows or not, so a page keeps its state.
- `WorkspaceTabPanes.tsx` (new): React `Activity` retention of the two list tabs on Android. A tab mounts on its first visit, is hidden later, and at most two are kept. iOS renders only the selected tab, because it already retains native tab trees.
- `WorkspaceTabsFrame.tsx`: bar on Android phones only; a split layout uses the rail.
- `HomeRouteScreen.tsx`: both branches render through `WorkspaceTabPanes`. A hidden tab gets an empty query, so it does not follow the other tab's search.
- `AdaptiveWorkspaceLayout.tsx`: `WorkspaceLocation.settingsOpen`, a rail slot that animates with the sidebar, pane widths that subtract the rail, and the rail overlay. The sidebar FAB wrapper was removed because New session is in the rail.
- `RootNavigator.tsx`: `settingsOpen` in the location, the settings `Stack.Group`, and Android Settings `animation: 'none'`.
- `routes.ts` and `workspace-tabs-state.ts`: doc comments only.
- `AndroidHomeFab.android.tsx` and `AndroidHomeFab.shared.tsx`: removed the orphaned `sidebar` prop, whose only caller was removed. These files are outside the named lane, are clean in git, and the edit is small.

Deliberate deviation from T3: a split layout does not hide the sidebar for Settings. Settings opens in the content pane beside the sidebar, as before. This avoids T3's open defect (a 200ms blank strip, then 130ms of overlap). T3's Thread-header flash fix, PR header row and filter menu changes, hide-on-scroll, and header-height alignment were not ported.

### #20327 iOS segmented control
- `NativeSegmentedControl.ios.tsx` (new) and a `.tsx` stub: UIKit's segmented control through the installed `@expo/ui` SwiftUI `Picker` with `pickerStyle('segmented')`. The wide iPad sidebar already uses this, so the native code compiles and no new module or package is needed. It keeps labels, the selected state (including external updates through `onChange(props.selection)`), compact versus default size (`controlSize` regular/large), per-option `accessibilityLabel`, and the light/dark appearance (`Host colorScheme`). UIKit supplies drag selection, VoiceOver traits, Dynamic Type, and reduced motion.
- `lib/native-segment-sync.ts` (new): a choice the caller refuses (for example, the review sheet while busy) remounts the control on the caller's value.
- `SegmentedControl.tsx`: now only chooses the platform control. The custom capsule was removed. `SegmentedControl.types.ts`: `indicatorClassName` was removed, since no platform reads it.
- Theme limitation: the per-theme PR track and selected colors (`pr-tab-track`, `pr-tab-selected`) are not carried. SwiftUI's segmented style does not apply custom segment colors, so iOS uses the system colors under the app's appearance. The PR caller no longer passes them.

### #21250 PR Share
- `lib/share-link.ts` (new): the payload follows each platform's contract (`{url}` on iOS; `{message: url, title}` with `dialogTitle` on Android). The result is `shared`, `dismissed` (an iOS cancel, which is not an error), or `failed` with a message. It uses React Native's built-in `Share`; there is no new dependency.
- `PullRequestScreen.tsx`: "Share…" in the iOS native header menu and the Android pill menu, with the same eligibility as Copy link (`pr` present, including the offline cached copy). A failure shows an alert. Copy link and Open on GitHub are kept.
- `AppSymbol.tsx`: Android icon map `square.and.arrow.up` → Tabler `IconShare`. This is additive, outside the named lane, and the file was clean in git.
- iPad: React Native presents an arrowless popover over the window, because a native menu item has no React tag to anchor to.
- Desktop and web: unchanged. Copy link and Open on GitHub are the surface-appropriate equivalents.

### Docs
- `docs/plans/mobile-pull-requests.md`: vocabulary (destination, navigation rail), the Navigation note, and new sections "Android destinations" and "Pull request detail". These replace the earlier two-root-tab rule on Android.
